# Stage 2 (Chapter 4): How Do Stakeholders Weigh Governance Against Efficiency in AI-Mediated Recruitment?

Replication code for Stage 2 (Chapter 4) of the doctoral thesis *Stakeholder acceptance of AI-mediated recruitment in Saudi higher education* (King's Business School, King's College London).

Stage 2 asks whether the acceptance of AI-mediated recruitment rests on the efficiency attributes of the Technology Acceptance Model, perceived usefulness and perceived ease of use, or whether the governance attributes of algorithmic transparency and ethical and privacy assurance carry independent weight when the two compete within a single choice.

## Contents

| File | Purpose |
|---|---|
| `01_prepare_conjoint.py` | Reads the raw Qualtrics export and the Stage 1 clean data, decodes the nine conjoint tasks for every respondent, checks the decoded data against the raw export and the Stage 1 exposure measures, and writes the choice data in long format with design checks and a codebook |
| `02_conjoint_analysis.py` | Runs every Stage 2 analysis and writes all tables (CSV), Figures 4.4 to 4.7 (PNG, 300 dpi) and a JSON file of key estimates |
| `requirements.txt` | Package versions used |

## How to run

The code was run with Python 3.13. Stage 2 uses the analytic sample defined in Stage 1, so the Stage 1 preparation script is run first.

```bash
python -m venv .venv
source .venv/bin/activate        # on Windows use: .venv\Scripts\activate
pip install -r requirements.txt
python ../stage1/01_prepare_data.py --raw path/to/survey_export.csv --out ../stage1/data
python 01_prepare_conjoint.py --raw path/to/survey_export.csv --stage1 ../stage1/data --out data
python 02_conjoint_analysis.py --data data --out outputs
```

All scripts are deterministic. The random seed for the bootstrap and for the selection of respondents checked against the raw export is fixed, so repeated runs reproduce every reported value.

## Data

The survey data are not included in this repository. Responses were collected anonymously under King's College London ethics approval MRSP-24/25-49508. The scripts expect the Qualtrics CSV export with its three header rows.

## Design

Each respondent completed nine forced-choice tasks between two AI recruitment profiles, with no opt-out. Each profile combined one level of four attributes.

| Attribute | Type | Levels, worst to best |
|---|---|---|
| Ethical and privacy assurance | Governance | Low, Moderate, High |
| Algorithmic transparency | Governance | Low, Moderate, High |
| Perceived usefulness | Efficiency | Low, Moderate, High |
| Perceived ease of use | Efficiency | Difficult, Moderate, Easy |

Profiles were generated by the Qualtrics conjoint module, which assigns each respondent one of 180 design versions. The order in which the attributes were listed was randomised for each respondent and held constant across that respondent's tasks.

## Data preparation

1. Start from the eligible respondents and the analytic sample defined by the Stage 1 preparation script, so that Chapters 3 to 5 rest on the same 317 respondents. The 26 respondents who failed the attention check are kept in a separate file for the robustness checks.
2. Locate each attribute through the respondent's own attribute order (`feature0.DISPLAY_NAME` to `feature3.DISPLAY_NAME`).
3. Decode the level of every attribute in every profile from the image code in the `_CBCONJOINT` columns, and the choice from `C1` to `C9`. The script stops with an error on any unrecognised attribute or level, a task without a valid choice, or a task that does not hold exactly two profiles.
4. Compare the decoded levels with the Stage 1 exposure measures, and read every attribute cell and choice again from the raw export for a random selection of 20 respondents. The script stops with an error on any discrepancy.
5. Flag choices in tasks where one profile dominated the other.

## Analyses

* Design diagnostics: level balance, independence of attributes, versions and profiles used, side and order effects, dominated pairs
* Average marginal component effects from a linear probability model, with standard errors clustered by respondent (CR1, t with G − 1 degrees of freedom) and Benjamini-Hochberg correction, the step from moderate to high within each attribute, tests of differences between attributes, and the minimum detectable effect
* Marginal means with clustered standard errors, omnibus F tests within attributes and tests against an even split
* Conditional logit with effects coding, part-worth utilities with delta-method standard errors, importance shares and the combined governance share
* Predicted choice between complete systems and trade-off ratios relative to perceived usefulness
* Respondent cluster bootstrap (2,000 samples) for every quantity derived from the conditional logit
* Robustness of the effects and importance shares across task halves, excluding the first task and fast responders, and including respondents who failed the attention check, with interaction tests for task half, linear task trend, profile side and attribute row position
